# Configuration Manager 2509 configuration

This collection provisions a fresh Configuration Manager 2509 evaluation primary site using the existing distribution point, SQL, management point, and site-server roles. Use `sccm-range-config.yml` as a standalone Ludus example. Existing sites from another build are rejected; use Configuration Manager in-console servicing for an in-place upgrade.

## Prerequisites and defaults

- Windows Server 2022 for the four site-system VMs.
- SQL Server 2022 with site database compatibility level 150.
- .NET Framework 4.8 or later, plus .NET Framework 3.5 for the setup bootstrapper.
- ADK 10.1.26100.9457 and its separate WinPE add-on (WinPE build 10.1.26100.1).
- ODBC Driver 18.6.2.1 and the x86 and x64 Visual C++ runtimes. Avoid ODBC 18.7.1.1 with Configuration Manager 2509.

The role defaults to the static Microsoft 2509 evaluation media URL and validates setup and installed site build 9141. It accepts successful setup exits 0 and 3010, then checks the SMS Provider. Existing 2303 caches can remain: site media and guest extraction are isolated by release, and ADK downloads have their own versioned cache. Console modules load through the installed ConfigurationManager module registration.

The example assigns 10 GiB to SQL and 6 GiB to the site server. SQL's memory limit defaults to 8192 MiB through `ludus_sccm_sql_max_memory_mb`; size it with room for Windows when changing the VM allocation. All SCCM hostnames must be at most 15 characters.

Enhanced HTTP defaults to enabled through `ludus_sccm_enhanced_http`. Client push, NAA and PXE retain their existing configuration switches. The service connection point is enabled by default.

The controller downloads primary installers and copies them to guests. Guest internet access is also required for ADK bootstrapper and setup prerequisite downloads. Existing incompatible ADK installations cause an explicit failure; remove the old ADK and WinPE add-on and reboot before retrying. Servicing readiness is checked before feature installation; align clocks and reboot the affected guest if that check fails.

## Optional proxy support

The collection does not configure an installer proxy by default, and service connection point proxy use defaults to off:

```yaml
ludus_sccm_setup_proxy_server: ''
ludus_sccm_scp_use_proxy: false
ludus_sccm_scp_proxy_name: ''
ludus_sccm_scp_proxy_account: ''
```

To opt in, supply the relevant site-server role variables. For example:

```yaml
ludus_sccm_setup_proxy_server: proxy.example.test:3128
ludus_sccm_scp_use_proxy: true
ludus_sccm_scp_proxy_name: proxy.example.test
ludus_sccm_scp_proxy_port: 3128
# Optional, for an authenticated proxy; the account must already be registered in ConfigMgr.
ludus_sccm_scp_proxy_account: 'EXAMPLE\proxyservice'
```

The installer proxy uses the installer account's Windows proxy settings and default credentials. The service connection point has a separate explicit proxy setting; if it needs authentication, configure an existing registered CM account. Configure the network and any proxy infrastructure separately. These options do not install a proxy server or depend on a particular domain or proxy role.

## Optional offline Windows feature source

When Windows Update is unavailable, set `ludus_sccm_windows_iso_path` to matching Windows Server installation media on the controller. The role uses a checksum-pinned extractor, copies only `sources/sxs` CAB payloads, and enables .NET 3.5 offline. The cache is keyed by the ISO SHA-256. Alternatively, set `ludus_sccm_windows_feature_source` to an existing guest payload directory. Both options default to empty, allowing Windows to use its normal feature source.

## PXE and operating-system content

Set `ludus_sccm_win11_iso_path` to override the OSD ISO location on any Proxmox storage pool. Changing the ISO does not replace previously imported images automatically. PXE configuration waits for the current OS and x64 boot-image content versions to reach each distribution point before completing.

DHCP clients must resolve the site-system FQDNs. If DHCP supplies a router as DNS, configure AD-domain forwarding to a domain controller in your own DNS infrastructure.

## Development checks

The repository includes generic configuration and PowerShell guard tests. Use Ansible core 2.16.12 with ansible.windows 2.7.0, install pytest and PyYAML, then run `pytest -q tests/test_configuration.py`. Run `tests/Test-VersionGuards.ps1` with Windows PowerShell 5.1. These development files are excluded from the built collection.
